PDF Pipeline Audit

Audit date: 2026-10-11. This report records implemented behavior, remaining gaps, quality risks, and next steps. The separate real-PDF validation report describes the sample-based checks and their limits.

目前流程

Input PDF → SHA-256/source copy → per-page profile → bounded page rendering → physical PDF batches → Docling/PyMuPDF → checkpoints → per-page JSON/quality state → chapter assembly → Markdown/source-page links → indexes/QA

長文件仍使用有上限的實體 PDF 批次；人類可見頁碼均為原始 PDF 的 1-based 全域頁碼。Manifest v1 以加法方式加入 page profiles、page images 與 page records。

Gap matrix

領域狀態現況與後續
頁面預檢與路由Partial以文字、圖片、向量圖形和覆蓋率產生建議；尚無完全獨立的逐頁 OCR/VLM 工作佇列，需以代表性資料校準。

失敗處理與續跑Implemented有界批次、雜湊檢查、原子狀態寫入、失敗頁狀態與選擇性重試皆有測試。

檢索與審核介面Partial / Not foundchunks 含頁碼來源；尚無向量檢索、圖像相似搜尋或 approve/edit/reject 審核 UI。

已知失敗與限制

  • PyMuPDF fallback 無法 OCR 影像頁；這類頁面會保留來源並標成 partial。
  • 結構 QA 通過不代表 OCR、表格或技術規格正確；人工抽查曾發現精確產品文字的辨識錯誤。
  • 逐頁 profile 與 numeric review 是啟發式，不代表事實驗證。
  • 遠端 OCR/VLM/LLM 可能傳送圖片與文字離開本機，必須在明確選擇及隱私審核後啟用。

優先路線

  1. 以非機密、有人工作標註的文字／掃描／技術圖／表格樣本校準 profile 與品質門檻。
  2. 評估真正的 OCR 與視覺審查佇列，量測準確率、記憶體、時間與頁面影像解析度。
  3. 加入表格對齊、prompt-injection 隔離、模型版本與執行資源紀錄。
  4. 先評估帶來源頁引用的關鍵字檢索，再決定是否需要向量或多模態索引。
