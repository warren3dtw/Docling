# 開發計畫流程

較大、跨模組或會改變使用者行為的工作，先在本目錄建立計畫。小型明確修正可直接實作，但仍需同步測試與文件。

## 檔名與生命週期

1. 建立 `YYYY-MM-DD-<feature-name>.md`。
2. 實作期間留在 `docs/plans/`，逐項更新 Tasks。
3. 驗證完成後移至 `docs/plans/archive/`，保留決策與最終結果。
4. 更新 `docs/FEATURES.md` 與 `docs/CHANGELOG.md`。

## 範本

```markdown
# 功能名稱

## User Story

身為 <角色>，我想要 <能力>，以便 <價值>。

## Spec

- 可觀察行為、輸入與輸出
- 相容性與安全界線
- 非目標

## Tasks

- [ ] 實作
- [ ] 測試
- [ ] 文件

## 驗證

- `uv run pytest`
- 針對功能的額外檢查

## 結果

完成後記錄差異、取捨與後續工作。
```

歸檔文件是決策紀錄，不表示其中所有通用建議都仍適用；目前行為以程式碼、`AGENTS.md` 與正式 docs 為準。
