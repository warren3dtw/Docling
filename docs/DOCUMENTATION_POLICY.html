規則

任何新增或修改的規則、工作流程、功能、內容或 App 操作方式，都必須在同一個變更中同步記錄為 Markdown 與 HTML。兩種格式必須呈現相同的核心資訊，不得讓其中一份落後。

全域狀態固定維護於 PROJECT_STATUS.md 與 PROJECT_STATUS.html；本規範固定維護於 DOCUMENTATION_POLICY.md 與本頁。

每次文件必備內容

  1. 最後更新日期與目前開發或交付階段。
  2. 已完成項目、進行中項目與下一步。
  3. App 安裝、啟動、操作或驗證方式。
  4. 測試與驗證結果。
  5. 已知限制、風險或尚未驗證事項。

更新流程

  1. 判斷變更是否涉及規則、流程、功能、內容或操作方式。
  2. 更新最接近主題的 Markdown；沒有合適文件時建立新文件。
  3. 同步更新同名 HTML，保持日期、狀態、指令和限制一致。
  4. 同步更新兩種格式的全域專案狀態。
  5. 在文件索引加入兩種格式的入口。
  6. 執行測試，並驗證 HTML 可解析、相對連結存在。

HTML 要求

  • 使用可直接開啟的完整 HTML，提供標題、導覽與清楚章節。
  • 版面需適合桌面與行動裝置，不依賴外部 CDN、遠端字型或 JavaScript。
  • 操作指令使用 <code> 或 <pre>，狀態與階段置於頁面上方。

驗證結果

本規範建立時，已同步新增 Markdown／HTML 規範文件與專案狀態頁，並將入口加入文件索引。

已知限制

目前 HTML 為人工同步維護，尚未由 Markdown 自動產生；每次變更必須透過審查與連結驗證避免內容漂移。
