預設每份 PDF 一份 DOCUMENT.md

使用者看到的文件

解析 batch 的大小控制記憶體和續跑範圍，不決定閱讀文件數量。解析完成後，語意章節整合到一份完整 Markdown。章節保留標題與錨點；INDEX 可跳至章節，chunks.jsonl 保留語意章節供檢索。

預設 output.max_markdown_pages_per_file: 100。100 頁內輸出 DOCUMENT.md；超過時在章節邊界輸出 PART-001.md 等檔案。單一章節也遵守相同頁數上限。

輸出位置

  • data/output/<id>/DOCUMENT.md：完整閱讀版。
  • data/output/<id>/PART-*.md：大型文件分段。
  • INDEX.md：連到文件中的章節錨點。
  • chunks.jsonl：既有欄位不變，來源路徑可連回章節。

重新匯出時會清除舊版自動產生的 chapters/ch-*.md。

目前套用情況

86 頁 CLT PDF 低於 100 頁上限，會整理成一份 DOCUMENT.md。64 個語意章節保留在文件內，檢索仍有 64 個章節 chunks。

重新匯出結果：DOCUMENT.md、INDEX.md、README.md 共三份 Markdown；不再有舊的章節 Markdown。完整文件大小 91,889 bytes，QA valid: true，broken links 為 0。

操作

uv run kb resume 26_clt_and_mass_timber_en_-32cd7da6637d --config config/default.yaml

修改 config/default.yaml 的 output.max_markdown_pages_per_file 後，重新執行 resume 或 build。這是輸出設定，不會使成功解析 batches 失效。

驗證與限制

  • 檢查文件頁數上限、章節錨點、圖片與來源頁連結。
  • 檢索仍使用細分的章節 chunks。
  • 整併只調整檔案與章節呈現，不會修正 OCR 錯誤；技術代碼仍需人工抽驗。
